# Планировщик дедлайнов и награды у фолловов

[English](FOLLOW-DROPS.md) · [Изменения релиза](RELEASE_NOTES.md)

Форк находит бесплатные награды у активных фолловов: обычные Drops и одноэтапные
WATCH reward groups. Дубли двух API объединяются по ID кампании и награды;
прогресс нового API имеет приоритет над устаревшим нулевым счётчиком. Платные,
заблокированные, полученные и истёкшие награды исключаются. Многодневные задания
остаются в прежнем режиме глобальных значков: `followDrops: false`.

## Установка и команды

Скачайте [релиз](https://github.com/w11hxhx/twitch-badge-farmer/releases), распакуйте
и выполните `./badge-farmer --gen-token` (Windows: `badge-farmer.exe`). Существующий
действующий config можно использовать повторно. Добавьте в приватную конфигурацию:

```json
{
	"followDrops": true,
	"scheduler": {
		"maxConcurrentStreams": 2,
		"historyEnabled": true,
		"priorityReward": "Точное название награды или campaignId:rewardId"
	}
}
```

Без `priorityReward` выбор автоматический. Один процесс на аккаунт.
Все команды принимают `--config /путь/account.json`.

```sh
./badge-farmer
./badge-farmer --channels
./badge-farmer --eligible-channels
./badge-farmer --plan
./badge-farmer --plan --json
./badge-farmer --set-priority "Точное название награды"
./badge-farmer --set-priority none
./badge-farmer --version
```

`--channels` показывает все фолловы, включая офлайн. `--eligible-channels`
(синоним `--scan-follows`) — доступные сейчас награды, каналы, прогресс, открытие
и закрытие UTC; отсутствующая дата — null. `--plan` учитывает ранее обнаруженные
офлайн-награды и показывает остаток минут, среднюю длительность стрима, прогноз
эфирного времени, оценку завершения, риск, слоты и причины выбора. JSON содержит
предупреждения. Команды списков не смотрят стримы, не забирают награды, не отправляют
уведомления и не записывают кеши планировщика.

`--set-priority` атомарно сохраняет выбор, владельца файла и приватные права.
Сервис перечитает настройки при следующем сканировании: обычно до трёх минут
плюс сканирование. Допустимы точное название, ID награды, campaignId:rewardId или
ID значка. Доступный приоритет удерживает слот до получения, ошибки или потери
доступности. Пока его канал офлайн, слоты используются для остальных наград.

## Прогноз и два потока

Вместо алфавитной ротации используется последний безопасный момент начала:
дедлайн, остаток просмотра, возраст текущего эфира и ожидаемое будущее эфирное
время. Выполнимые награды предпочтительнее уже невыполнимых, кроме приоритета.

Источник — публичные 30-дневные агрегаты `https://lurkology.com/КАНАЛ/streams`:
средняя длительность стрима и число эфиров в день. Авторизация не нужна. Запросы
ограничены по времени, выполняются по три и кешируются на шесть часов. Прогноз
оставляет запас 20% эфирного времени. Кеш старше семи дней заменяется явно
обозначенной запасной оценкой. Источник и неопределённость видны в плане.
Время завершения — прогноз, а не объявленное стримером расписание.

Работают максимум два независимых потока разных каналов/кампаний. Twitch не
гарантирует параллельный зачёт Drops. Пока серверные счётчики не выросли у обоих,
проверка общей нагрузки предполагает **один** рабочий слот. Если приоритет не
продвигается три минуты, второй поток отключается на 30 минут. Нет прогресса
пять минут — перепланирование и возможное отключение параллельного просмотра.
Новая пара проверяется заново. Два канала одной кампании не удваивают время.

Все дедлайны гарантировать невозможно: стример может не выйти в эфир или закончить
раньше, награды конкурируют за время, Twitch может не засчитать второй поток.
Вместо обещаний план показывает риск каждой награды и конфликты общей нагрузки.

## Уведомления и внешний статус

Добавляйте только нужные секции. По умолчанию ничего не отправляется:

```json
{
	"notifications": {
		"telegram": { "token": "123456:BOT_TOKEN", "chatId": "123456" },
		"discord": { "webhook": "https://discord.com/api/webhooks/123456/WEBHOOK_TOKEN" },
		"webhook": { "url": "https://example.com/private-hook" }
	}
}
```

Telegram редактирует одну карточку обоих активных потоков. ID сохраняется между
перезапусками; неизменившийся текст пропускается, удалённая карточка восстанавливается,
при HTTP 429 соблюдается retry_after. Событийные сообщения остаются отдельными.
Discord/HTTPS получают события, а не ежеминутный прогресс. Явная проверка адресатов:
`--test-notifications`.

Приватные атомарные файлы рядом с конфигурацией:

- `.history.state.json` — публичная статистика и время получения.
- `.planner.state.json` — известные награды, включая офлайн, и подтверждённые получения.
- `.status.json` — аккаунт, активные каналы, прогресс, приоритеты, оценки, предупреждения.
- `.notifications.state.json` — ID Telegram-сообщения и отпечаток адресата, без токена.

Внешний бот баллов и бейджей может читать `.status.json`. Персональный мост VPS и
Telegram-реквизиты в репозиторий не входят. Награду подтверждает только Twitch.

## Сборка и обновление

```sh
bun install --frozen-lockfile
bun run typecheck
bun test src
bun run format:check
bun run build
```

Архивы: Windows x64, Linux x64, macOS arm64, macOS x64, с SHA-256.
Перед заменой остановите старый экземпляр; сохраните config и состояние для отката.
Повторная авторизация не нужна, пока существующий токен действителен.
