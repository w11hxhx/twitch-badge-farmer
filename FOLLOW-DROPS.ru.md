# Drops у отслеживаемых каналов

## Списки каналов и наград

```sh
./badge-farmer --channels --config /path/config.json
./badge-farmer --eligible-channels --config /path/config.json
./badge-farmer --eligible-channels --json --config /path/config.json
```

На установленном VPS доступна короткая команда с уже заданным путём конфигурации:

```sh
twitch-badge-farmer --channels
twitch-badge-farmer --eligible-channels
twitch-badge-farmer --eligible-channels --json
```

`--channels` показывает **все ваши фолловы**, включая офлайн, с состоянием LIVE/OFFLINE.
Это не глобальный список всех каналов Twitch. `--eligible-channels` и его синоним
`--scan-follows` показывают доступные сейчас награды у активных фолловов, каналы,
прогресс и даты `openedUTC`/`closesUTC`. Для reward groups используются даты
кампании; если Twitch их не сообщил, выводится `null`. Даты всегда UTC.
Эти команды не запускают просмотр, не собирают награды и не отправляют уведомления.

Одна награда, доступная на нескольких каналах, занимает одну строку со списком
каналов. В сводке отдельно указаны активные фолловы, подходящие каналы,
уникальные награды и пары «канал — награда». В список входят и обычные Drops
(включая игровые предметы), и одноэтапные WATCH reward groups. Поэтому число
строк не означает количество новых значков. Для reward group без отдельного
названия используется название кампании с пометкой `/ WATCH`; если Twitch
не предоставил и его — ID значка или группы.
JSON для наград имеет форму `{ "rewards": [...], "warnings": [...] }`;
предупреждения означают, что отдельные каналы проверить не удалось. Для
`--channels --json` возвращается массив каналов с полями `id`, `login`, `live`.

Если Twitch показывает одну награду через старый Drops API и новый reward-group
API с одинаковыми ID кампании и награды, записи объединяются и в списке, и в
очереди просмотра. Читаемое название берётся из Drops, а прогресс и способ
подтверждения — из reward group: старый API для таких наград может показывать
нулевой прогресс вместо фактически накопленного времени.

## Telegram: редактируемая карточка прогресса

При настроенном Telegram сервис создаёт одно тихое сообщение статуса для аккаунта,
а затем редактирует его через `editMessageText`. В нём: награда, канал, минуты,
процент, оставшиеся минуты просмотра, даты открытия и закрытия UTC, состояние
просмотра/получения. При переключении канала обновляется эта же карточка.
Прогресс проверяется раз в минуту; если текст не изменился, запрос не отправляется.
Обычные уведомления о новых наградах и событиях по-прежнему приходят отдельно.
Discord и webhook не получают ежеминутный прогресс.

ID сообщения сохраняется рядом с конфигурацией в
`config.json.notifications.state.json` (права 0600, атомарная запись).
После перезапуска используется прежнее сообщение. Токен бота в файл состояния
не записывается. Если сообщение удалили, сервис создаёт новое; при других ошибках
не создаёт копии, а при HTTP 429 соблюдает `retry_after`. Файл состояния привязан
к боту и чату: смена настроек создаст сообщение в новом месте.

Никаких новых Telegram-реквизитов для использования списков или просмотра не нужно.
Без секции `notifications.telegram` карточка отключена, запросы в Telegram отсутствуют.

Этот форк добавляет режим `"followDrops": true` в существующий `config.json`.
Список фолловов берётся у Twitch с пагинацией. Проверяются только активные
трансляции, обычные временные Drops и одноэтапные WATCH reward groups.
Каталог StreamDatabase для этого режима не требуется. `PepeLand 11 START`
обнаруживается как обычная временная награда у pwgood, когда канал в эфире.

Каналы равноправны: выбор по кругу в алфавитном порядке, один канал за раз,
до 30 минут на канал. Затем очередь переходит дальше. Если серверный прогресс
не растёт 5 минут, канал временно исключается. Сканирование повторяется через
3 минуты после завершения предыдущего. Прогресс запрашивается раз в минуту.
Прогресс хранит Twitch; локально прошедшее время не считается доказательством награды.
Длительное сканирование поддерживает активную сессию просмотра.

Готовые обычные Drops забираются по `dropInstanceID`, успех подтверждается
последующей проверкой инвентаря. Reward groups с несколькими днями, выбором
ветки и платными условиями пропускаются. Для прежнего режима глобальных
значков, включая многодневные задания, установите `"followDrops": false`.
Режимы работают по отдельности, чтобы не создавать параллельный просмотр.

Равная очередь не гарантирует завершение конкретной награды до дедлайна.
Не запускайте второй экземпляр для этого же аккаунта.

## Уведомления (по умолчанию отключены)

Добавьте только нужные секции в свой приватный `config.json`:

```json
{
	"id": "your_twitch_id",
	"login": "your_twitch_login",
	"client_id": "ue6666qo983tsx6so1t0vnawi233wa",
	"token": "your_oauth_token",
	"followDrops": true,
	"notifications": {
		"telegram": { "token": "123456:BOT_TOKEN", "chatId": "123456" },
		"discord": { "webhook": "https://discord.com/api/webhooks/123456/WEBHOOK_TOKEN" },
		"webhook": { "url": "https://example.com/your-private-hook" }
	}
}
```

Telegram: создайте бота через BotFather и сначала напишите ему. Discord:
создайте webhook нужного канала. Универсальный HTTPS webhook принимает
JSON `{ "event": "watching", "message": "..." }`; его можно связать с
собственным шлюзом, n8n или другим сервисом уведомлений.

События: доступна награда, начат просмотр, прогресс остановился, отправлен
запрос получения, получение подтверждено. Повторы подавляются на 15 минут
в рамках процесса. Ошибка доставки не останавливает просмотр; один запрос
ограничен 10 секундами. Discord упоминания отключены. Содержимое ответа,
токены и URL webhook не выводятся в ошибках доставки.

`./badge-farmer --test-notifications --config /path/config.json` отправит
тестовое сообщение всем настроенным адресатам. Без настроек сеть не вызывается.
Настоящая доставка требует действующих реквизитов; автоматические тесты
используют подменённый HTTP транспорт, проверяя payload, ошибки HTTP/API,
сетевые сбои, отсутствие реквизитов и подавление повторов.

## Проверка и развёртывание

```sh
bun install --frozen-lockfile
bun run typecheck
bun test src
bun run build
./dist/badge-farmer --scan-follows --config /path/config.json
```

`--scan-follows` только читает Twitch, не смотрит трансляции, не забирает
награды и не отправляет уведомления. Перед заменой бинарника остановите
существующий сервис и сохраните бинарник, конфигурацию и файл состояния.
Затем установите новый бинарник, включите `followDrops` и запустите сервис.
Секреты остаются в существующем файле конфигурации на сервере.
